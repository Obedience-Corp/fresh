# Fresh terminal demos

These VHS recordings show real Camp running against a disposable `site` project.
The setup recording opens `camp fresh configure`, adds `npm ci` and `npm run build`
through its forms, and saves them for the detected project. The cleanup recording
previews the saved workflow, removes a merged branch, and runs both follow-ups.

The fixture contains a small Node site with no external dependencies. Its build
copies the source page into `dist/`. No output is mocked. The recording script
checks the saved workflow after the TUI closes, then checks the branch, remote
alignment, clean Git status, and built file after cleanup.

## Re-record the Camp demos

Requirements: Docker, VHS, its terminal/browser dependencies, FFmpeg, Python 3,
and Linux builds of `camp` and `fest`. Use binaries matching the container
architecture; the default is `linux/amd64` (`CAMP_DEMO_PLATFORM` overrides it).

From the repository root:

```bash
CAMP_BIN_DIR=/absolute/path/to/linux-binaries bash docs/demos/record.sh
```

Choose an isolated Docker daemon through `DOCKER_HOST` if your development setup
uses one. The script mounts the binaries and this repository read-only. All Camp,
Git, and npm operations run inside a fresh container; the script removes that
container on exit. VHS writes only the recordings and stills into this directory.
It does not install or replace the host's Festival tools, or publish the recordings.

- [configure.tape](configure.tape): project setup through the TUI.
- [cleanup.tape](cleanup.tape): preview, cleanup, and saved follow-ups.
- [setup-fixture.sh](setup-fixture.sh): the isolated project and merged branch.
- [record.sh](record.sh): capture, persisted-state checks, and still extraction.

The GIFs play inline on GitHub and start near the result so static previews show
the workflow or cleanup outcome. MP4s preserve the original sequence and provide
playback controls when opened in a video viewer; the stills show the final saved
workflow and cleanup result. VHS's
hidden sections enter the container and clear the terminal before recording the
user-facing commands. The cleanup clip clears the preview before showing the run.

## Record the skill in Codex

[skill.gif](skill.gif) and [skill.mp4](skill.mp4) record a real Codex CLI 0.162.1
session using the installed Fresh plugin. VHS opens `/skills`, selects **List
skills**, filters for `fresh`, and selects **fresh (fresh)**. Codex inserts
`$fresh:fresh`; submitting it loads the skill, runs its Festival check, displays the preview, performs
cleanup, and reports the result. The responses and tool output are generated by
Codex during capture. [skill-run.json](skill-run.json) contains the verified
preview and run output from that session.

The fixture starts with Festival present, the plugin installed with `codex plugin
marketplace add /fresh` and `codex plugin add fresh@fresh`, a linked repo, one merged branch, and saved install/build
commands. This demonstrates skill invocation, not installation or desktop app
rendering. The GIF starts near the result for its static preview; the MP4 retains
the original sequence and timing.

Use an existing Codex `auth.json` login. The script mounts that single file
read-only for Codex authentication. It does not copy it into this repo or export
raw agent session logs. The agent works on the disposable fixture with the installed skill. The verifier exports fixture output and
check names, excluding account, usage, and authentication data.

```bash
CAMP_BIN_DIR=/absolute/path/to/linux-binaries \
CODEX_AUTH_FILE=/absolute/path/to/codex/auth.json \
bash docs/demos/record-skill.sh
```

The script installs the pinned Codex CLI in a fresh Node container and removes the
container on exit. The default platform is `linux/arm64`; set
`CAMP_DEMO_PLATFORM=linux/amd64` for a native x86 Docker daemon. Run Codex natively:
its terminal runtime did not work under x86 emulation in the recording environment.
Camp/Fest binaries must be executable in the selected container.

The demo allows commands without approval inside this disposable container.
Host project files and binaries are mounted read-only. These recording settings
are not instructions to disable protections in a user's working repository.

- [skill.tape](skill.tape): the actual prompt and terminal capture.
- [record-skill.sh](record-skill.sh): container setup, capture, and cleanup.
- [verify-skill.py](verify-skill.py): proves native plugin selection and instruction loading, installer invocation,
  preview before execution, exact report count, and persisted cleanup/build state.

Agent responses and timings can vary. A recording fails verification if the agent
does not complete the expected workflow. Review the resulting footage before
committing it; no generated response is substituted with a scripted success.
